01 React 心智模型：UI、DOM 与更新

快速理解 React 用组件描述 UI。它把你写的 JSX/TSX 转成可比较的表示，再只把需要的变化更新到页面的 Real DOM。

课程中的 React

课程将 abstraction 解释为用较简单的 API 隐藏复杂技术细节。HTML 管结构、CSS 管表现、JS 管行为；页面和重复 UI 增多时，维护、复用、state 与数据请求更难组织。

  • React（React.js / ReactJS）：由 Meta（原 Facebook）的工程师 Jordan Walke 创建，是专注 UI/组件的开源 JavaScript library。
  • 课程关键特性：Virtual DOM、performance、one-way data binding、simplicity、JSX/TSX 和 components。
  • 课程的 simplicity：起步时可继续使用已学的 HTML、CSS、JavaScript，而 React 处理其余 UI 工作。

JSX/TSX 编译提示

讲义以“你写的 JSX/TSX”和 React 编译后看到的 _jsx() 调用作对比。_jsx() 是理解编译结果的提示，不是当前需要手写的 React 代码。

DOM：HTML 文档的树状结构；Real DOM 是 UI 中实际结构
Virtual DOM：内存中的 DOM 表示
 ↓
UI 变化 → 比较前后表示（diffing）
 ↓
Reconciliation：把需要的变化更新到 Real DOM

课程的性能与列表心智模型

  • 课程用 reconciliation 说明 React 避免冗余 DOM 重渲染，并以 Diffing Algorithm 的 O(n) 对比早期 O(n³) 的性能叙述。
  • 这是课程性能心智模型，本页不把该简化复杂度叙述扩展成通用性能定律。
  • 列表中 React 需识别每一项时使用 key；课程说明有些 key 需开发者通过 props 指定。

02 组件、Props 与单向数据流

快速理解 组件把可重复 UI 变成可复用函数；props 是 parent 传给 child 的数据。数据方向保持 Parent → Child。

Component 是通常返回 JSX/TSX 输出的函数，也可包含其他 component。把重复 UI 写一次再复用，符合 DRY。单向数据绑定是 Parent → Child：父组件在 JSX/TSX 中用自定义属性传数据，属性值叫 props；课程以此说明可读性和可维护性。

// Parent.tsx
<Child optimist={optimist} />
// Child.tsx
interface ChildProps { optimist: string; }
function Child(props: ChildProps) { return <h2>{props.optimist}</h2>; }

读取组件 JSX/TSX

  • <Child /> 是 JSX/TSX 中的组件引用。{ } 从标签内的文本/XML 切换到 JavaScript 表达式范围，因此可读变量和 props。
  • ? 与 : 是 ternary expression（if/else 简写）的操作符；课程示例用 Unicode ☺ / ☹ 决定显示哪个表情。
  • children 是 parent 传给 child 的占位 JSX/TSX 内容。
  • return() 只能返回一个外层元素（其内可含其他元素/组件）；不想产生额外 DOM 包装时用 React Fragment：<>...</>。若 return 内容只有一行，圆括号可以省略。

03 JSX / TSX

TSX 与 HTML 的关键差异

TSX 让标签、CSS、JS 和 TypeScript 类型在组件文件协作；这里 TypeScript 是“JS + 类型声明”。

HTMLJSX / TSX含义
classclassName使用 JSX/TSX 属性名。
maxlengthmaxLength属性使用 camelCase。
style stringstyle={{color: 'blue'}} object内联样式改为 object。
onclick="fn()"onClick={fn}传函数引用。
<!-- -->{/* */}使用 JSX/TSX 注释语法。
<img><img />自闭合标签必须写成自闭合形式。
常见错误：事件处理提前执行 onClick={handleClick()} 会在渲染时调用；用 onClick={handleClick} 传引用。匿名写法可为 onClick={() => console.log('Hello World!')}。

04 样式与组件组织

组件文件与命名

  • 组件必须先 export 才能被 import；遵循单一职责时，一个文件只有一个主要组件，常用 export default。
  • 课程命名约定：组件文件、函数和功能变量首字母大写，文件名与组件名对应，例如 Sample.tsx 包含 Sample；小写会被 React 当成普通 HTML 标签。

styled-components

styled-components 是本学期会使用的 CSS-in-JS library；名字首字母大写，反引号中的 string interpolation 写 CSS。

const StyledHeader = styled.h1`
  color: blueviolet;
`;

05 Vite 项目与文件职责

课程环境与创建流程

课程环境需要全局安装的 Node.js（不是 Java JRE）和 Vite；讲义列出按平台更新全局 npm 的命令，执行前应确认课程和本机要求。项目可在 Terminal/CMD 或 IDE 中创建。

  1. npm create vite@latest；项目名使用 spinal-case，例如 mp-2。
  2. 选择 React，再选择 TypeScript + SWC（Node.js compiler）。
  3. cd mp-2 → npm install → npm run dev。

清理与入口文件

  • Vite 默认文件（如 vite.svg、react.svg、App.css）及其引用可删除；每删一步重跑，防止漏掉引用。
  • index.html 保留 boilerplate/root；main.tsx import App 并 createRoot(...).render(<App />)；App.tsx 是主组件。

06 useState、useEffect 与 API

const [numArtworks, setNumArtworks] = useState(5);
const [artworks, setArtworks] = useState<ArtworkProps[]>([]);
useEffect(() => { async function fetchArtworks() {
  const response = await fetch(`...artworks?limit=${numArtworks}`);
  const json = await response.json(); setArtworks(json.data);
} fetchArtworks(); }, [numArtworks]);

input 改变 → setNumArtworks(Number(e.target.value))
 ↓
numArtworks 改变 → useEffect 再请求
 ↓
response.json() → setArtworks(json.data)
 ↓
artworks.map(...) → 一个 ArtworkPreview / artwork

State、effect 与渲染各做什么

  • useState 给当前 state 与 setter；此例初始数量为 5、列表为空。
  • useEffect 在 numArtworks 改变时重新 GET。
  • map 用匿名函数返回 ArtworkPreview，{...artwork} 展开对象字段为 props。

课程任务顺序

  1. 初始化。
  2. 创建 ArtworksListContent，用 input 观察 state。
  3. 定义 ArtworkProps，建并 mock-test ArtworkPreview。
  4. 按 limit GET Chicago Art Institute API、解析并用 map 显示。
Optional work错误处理、只请求所需字段和过滤仍是 optional work。
