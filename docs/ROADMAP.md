# Roadmap

## Foundation V1 → knowledge-led growth

Foundation design is closed. The normal next step is to use the automated ingestion workflow for new course material, debugging experience, projects, and new technologies—not to perpetually redesign the interface. Ingestion maturity means increasingly reliable source inventory, detail accounting, conflict labeling, bilingual parity, and source-index/changelog updates.

- **HTML / CSS / JavaScript / Git:** grow only from studied or user-provided evidence; preserve current domain boundaries.
- **React:** becomes a separate knowledge area when sufficient source material exists; never blend it into JavaScript merely because it appears nearby.
- **Web/API/backend:** HTTP, request/response, headers, JSON, REST, FastAPI, and related material may become a cross-cutting or new domain only when conceptually justified by actual learning evidence.
- **Learning Instruments:** extend only when a demonstrated learning problem needs a new bounded pattern. High-value candidates are nested-loop traces, CSS cascade/source-order tracing, and Git branch/merge state transitions. Arbitrary JavaScript execution remains explicitly out of scope.
- **Optional asset:** a dedicated Git repository/history industrial 3D object may be added only when a suitable rendered asset exists; it is not a product blocker.

System expansion—new navigation, page architecture, instrument family, dependency, design language, or visualization runtime—is exceptional. Use the existing system unless it cannot clearly represent the new knowledge.

This is a direction record, not tutorial content or proof that these topics are already learned.
