# Design and Knowledge-Page Contract

## Baseline

Foundation V1 is established: Technical Editorial × Industrial Graphic Design × Developer Tool Precision × Learning UX. Preserve the live system during ordinary work. Visual changes need a learner/browser reason; browser-rendered evidence is stronger than static checks.

## Knowledge-page rules

- Keep global navigation consistent: Home → HTML → CSS → JavaScript → Web Data → React → Git → language controls. Only the active state varies.
- Use concise, independently meaningful sidebar labels.
- Preserve hierarchy through typography, whitespace, rules, vertical sequencing, and progressive disclosure before adding cards.
- Cards/callouts have semantic roles: Quick Understanding, Concept, Example/Code, Process, Comparison, Note, Pitfall, or Key Point. Do not require every role in every section.
- Use code for implementation; tables for comparison/reference; ASCII for compact developer relationships; diagrams for relationships that need spatial clarity.
- Interaction must encode or clarify knowledge. Use it only when learners can cause, observe, compare, trace, select, step through, predict, or verify a bounded behavior. Default content remains complete without JavaScript.
- Maintain bilingual visible content and responsive vertical recomposition. Preserve knowledge before decoration on narrow screens.

## Visual language

Paper `#F1F0E8`, ink `#161714`, steel `#70736D`, hairline `#CACBC3`, lime `#C7E51B`, cyan `#35AFC2`, and red `#D94A3D` retain semantic meaning. Prefer alignment, hairlines, labels, restrained feedback, and purposeful motion over generic cards, glow, bounce, or decorative animation. Respect reduced motion.
